# ADR 0001: 外部モデルパック互換性維持のための独自描画ラッパーとGLブリッジの継続利用

## ステータス

承認済み (Accepted)

## コンテキスト

Minecraft 1.20.1 から 1.21.2 へのアップデートに伴い、バニラのレンダリングパイプライン（`RenderType`、`VertexFormat` 等）に破壊的変更が行われました。
LittleMaidNeo では、既存の多数の外部モデルパック（`.class` 形式で配布されているモデル定義）との互換性（保護コア A）を維持することが極めて重要です。これらの外部パックは、メイドさん固有の `maidmodel/` ジオメトリ、`EntityCaps`、`IModelCaps`、`ModelRenderer` などのシグネチャに強く依存しており、これらを変更するとランタイムでの `LinkageError` や `AbstractMethodError` を引き起こします。

GeckoLib や AzureLib などのモダンなアニメーションライブラリへの移行、あるいはバニラの `ModelPart` / `LayerDefinition` への完全な移行を検討しましたが、以下の問題が生じます：
- `ModelPart` ベースのバニラ描画システムは、`maidmodel/` 独自ジオメトリと構造的な互換性がありません。
- 完全移行を行うと、外部モデルパックが無改変でロード・描画できなくなり、最優先されるべき「保護機能①」が破壊されます。

現在、`GLCompat` と `multimodel/layer` パッケージ（`MMMatrixStack`, `MMVertexConsumer`, `MMPose`, `MMRenderContext`）が、バニラ 1.21.2 の現代的描画システムへのブリッジとして機能し、安定して動作しています。

## 意思決定

既存の外部モデルパック（SR2, AC, RX0, Steve等）との無改変での描画・動作互換性を100%維持するため、以下の意思決定を行います：

1. **メイドさん本体の GeckoLib/AzureLib およびバニラ `ModelPart` への移行は見送る**
   - 外部パック用に旧描画パスを並行維持するなどの複雑な二重描画システムは導入せず、安定している現行のブリッジ構造を一元的に維持します。
2. **独自描画ラッパー（`MMMatrixStack` 等）の維持と内部のバニラ委譲**
   - 既存のアダプタ構造を維持し、外部モデルパックから見えるシグネチャを一切変更せずに、内部実装のみをバニラ標準型（`PoseStack` 等）に委譲する現行アプローチ（方針 b）を継続します。
3. **新規の補助エンティティに限定したモダン描画の適用**
   - 将来的に GeckoLib やバニラ `ModelPart` を使用する場合は、外部パック互換性を考慮する必要のない、新規に追加する補助エンティティや別オブジェクトのみに限定して適用します。

## 結果

- **保護コア A の維持**: 既存の外部モデルパックが一切の改変なしにランタイムでロードされ、メイドさん本体および各種モデルが正常に描画される互換性が完全に担保されます。
- **保守性の確保**: 複雑な ASM 動的リマップや Transformer によるブリッジ生成を行うことなく、安定した薄いアダプタクラスにより 1.21.2 対応と互換性をシンプルに両立させることができます。
- **リスクの最小化**: 最も高いリスクとされるレンダリング周りの大規模破壊的変更を回避し、システムの安定稼働を確保します。
