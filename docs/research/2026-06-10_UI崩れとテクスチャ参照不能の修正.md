# UI 崩れ・テクスチャ参照不能バグの根本原因と修正

- 日付: 2026-06-10
- 種別: research / fix
- 関連: docs/research/2026-06-03_resources整理とPR10部分マージ是正.md（「UI 崩れの継続調査」）

## 根本原因 1: `GuiGraphicsExtractor.blit` のオーバーロード取り違え（UI 崩れの本体）

MC 26.1 の `blit(Identifier, ...)` 9 引数版のシグネチャは

```java
blit(Identifier location, int x0, int y0, int x1, int y1, float u0, float u1, float v0, float v1)
```

であり、**第 4・5 引数は「右下の絶対座標」、float 4 つは 0..1 の正規化 UV**（`innerBlit` 直結）。
本プロジェクトは旧 `blit(tex, x, y, width, height, u, v, uWidth, vHeight)`（ピクセル指定）の
感覚で呼んでいたため、

- 描画矩形が `(relX, relY)-(176, 208)` のような壊れた範囲になる
- `u1=0`（幅ゼロの UV）や `v0=176`（範囲外 UV）でテクスチャが正しく参照されない

→ 「UI が崩れ、テクスチャが参照できない」見た目になっていた。コンパイルは通るため CI では検出不能。

### 修正

ピクセル指定の正規オーバーロードへ移行:

```java
context.blit(RenderPipelines.GUI_TEXTURED, texture, x, y, u, v, width, height, textureWidth, textureHeight);
```

対象: `LittleMaidScreen` / `ModelSelectScreen`(×3) / `SoundPackSelectScreen` / `ScrollBar`
（`TextureAddress` が保持していた `texSizeW/texSizeH` を初めて実際に使用）。

シグネチャの根拠: MC 26.1 デコンパイルソース（`GuiGraphicsExtractor#blit` → `innerBlit` で
`u0/u1/v0/v1` をそのまま頂点 UV に使用、ピクセル版は `(u + srcWidth) / textureWidth` で正規化）。

## 根本原因 2: `ResourceWrapper` の pack format 固定値 15

外部モデルパックのテクスチャは `ResourceWrapper`（仮想リソースパック）経由で解決されるが、
`PackMetadataSection` が `PackFormat.of(15)` を名乗っていた。MC 26.1 のクライアントリソース
format は major 64 以降（`PackFormat.lastPreMinorVersion(CLIENT_RESOURCES) == 64`）のため
「非互換パック」扱いとなり、外部テクスチャの参照が落ちる。

### 修正

```java
new InclusiveRange<>(SharedConstants.getCurrentVersion().packVersion(PackType.CLIENT_RESOURCES))
```

実行中バージョンの format を常に名乗ることで、MC 更新時にも再発しない。

## 検証

- ローカル環境は maven.neoforged.net 遮断のためコンパイル不可。CI（Java 25）で検証。
- 実機確認項目: `LittleMaidScreen` の背景描画、モデル/サウンドパック選択画面の背景・
  切替ボタン・スクロールバー、外部パックテクスチャの解決。
