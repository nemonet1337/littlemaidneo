# メイドさん挙動不具合の調査と修正

- 日付: 2026-06-03
- 種別: research / fix
- 関連: Phase 7/8 Brain 移行（commit 3f81261 ほか）、MC 1.21.4+ アイテムモデル刷新

## 背景

ユーザーから以下の不具合報告を受けた。

1. メイドさんが移動しない
2. プレイヤーに追従しない
3. スポーンエッグと UI のデザインが崩れている／テクスチャが読み込まれない
4. 武器を持たせてもモード変更をしない
5. ワープ後に砂糖をあげても待機にならない
6. 各種モード変更に不備がある
7. 契約前のメイドさんが歩かない
8. プレイヤーを目で追いかけない

## 根本原因と修正

### A. 移動が一切発生しない（1・2・7、結果的に 8 にも影響）

`LittleMaidEntity.BRAIN_PROVIDER` の Brain（CORE アクティビティ）には移動を駆動する
`MoveToTargetSink` が登録されており、各 Behavior（FollowOwner / Freedom / Stare）が
`WALK_TARGET` メモリを設定する設計。しかし **`MoveToTargetSink` の起動要件に
`MemoryModuleType.PATH`（VALUE_ABSENT）が含まれる**（26.1.x の decompile で確認）。

`Brain.checkMemory` は「未登録のメモリ型に対しては status を問わず常に false」を返すため、
PATH を provider のメモリリストに登録していないと `MoveToTargetSink` が永久に起動せず、
`WALK_TARGET` が消費されない → ナビゲーションが動かない＝移動・追従・徘徊がすべて不発。

> 補足: CORE アクティビティ自体は `Brain` コンストラクタが `setCoreActivities(CORE)` +
> `useDefaultActivity()` を行うため自動で有効。アクティベーション漏れではなくメモリ未登録が原因。

**修正:** `BRAIN_PROVIDER` のメモリリストへ `MemoryModuleType.PATH` を追加。

### B. スポーンエッグ／UI のテクスチャ破損（3）

- **スポーンエッグ:** 旧モデルは `parent: minecraft:item/template_spawn_egg` を参照していたが、
  この親モデルは 26.1.2 では **削除済み**（mcmeta で 404）。加えて MC 1.21.4+ では全アイテムに
  `assets/<ns>/items/<item>.json`（クライアントアイテムモデル定義）が必須だが未整備だった。
  - モデルを `item/generated` + 専用テクスチャ方式へ変更（バニラの現行スポーンエッグと同方式）。
  - テクスチャは旧 LMMBase 履歴の `lmreengaged/textures/items/spawn_littlemaid_egg.png` を復元し
    `textures/item/little_maid_spawn_egg.png` として配置。
  - `items/little_maid_spawn_egg.json` / `items/salary_box.json` を新規作成。
- **インベントリ UI:** `LittleMaidScreen` の背景テクスチャが存在しない `lmreengaged` 名前空間を参照。
  旧 LMMBase 履歴の `littlemaidinventory2.png`（256x256）を復元し本 Mod 名前空間へ配置、参照を修正。
- **ハート/防具アイコン:** `minecraft:textures/gui/icons.png` は 1.21 のスプライト化で廃止済み。
  blit 依存を塗りつぶし矩形（`context.fill`）での簡易バー描画に置き換え。

### C. 武器でモードが切り替わらない（4・6）

`HasModeImpl.tick()` はモード未設定時 `getNewMode()`（**メインハンドのみ**走査）に依存していた。
メイドさんに武器を「持たせる」＝インベントリ投入のため、メインハンドが空だとモード判定されない。

**修正:** メインハンドにモードアイテムが無い場合、インベントリを Priority 降順で走査し、
最初にマッチしたモードアイテムをメインハンドへ装備してモードを有効化する
（`equipModeItemFromInventory()`）。

### D. 砂糖で待機にならない（5）

待機状態は `orderedToSit` が真実値で、Brain の `IS_WAITING` メモリへは `LittleMaidSensor` が
**20 tick ごと**にしか同期しない。砂糖で待機を切り替えた直後の最大 1 秒間は Behavior が反応せず、
追従/ワープ中だと「待機にならない」ように見える。

**修正:** `TameableUtil.setWait/switchWait` で `IS_WAITING` メモリを即時同期（`syncWaitMemory`）。
Sensor は初期化・保険として従来どおり維持。

### E. プレイヤーを目で追わない（8）

`LookAtPlayerGoal` を既定確率（0.02）で登録していたため稀にしか視線が向かなかった。
移動不能（A）で体の向きも固定されることと相まって「目で追わない」と認識されていた。

**修正:** A の修正に加え、プレイヤー優先の `LookAtPlayerGoal`（確率 0.8）を追加登録。

## 検証メモ

- 当環境では Java 25 ツールチェーンが未提供（ネットワークポリシーで foojay 取得不可）のため
  `./gradlew compileJava` を実行できず、変更はソースレビューで確認した。
  使用 API（`MemoryModuleType.PATH` / 5 引数 `LookAtPlayerGoal` / `Brain#setMemory` /
  `GuiGraphics#fill`）はいずれも当バージョンに存在することを確認済み。
- ビルド可能環境での `runClient` による実機確認を推奨。
